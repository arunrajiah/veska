# ADR 003 — ORM

**Status:** Accepted  
**Date:** 2026-05-13

## Decision

Drizzle ORM with Drizzle Kit for migrations.

## Rationale

- SQL-first philosophy means queries are readable and predictable — important for a project that will be audited by the community.
- Best-in-class TypeScript inference: column types flow through to query results without extra type assertions.
- Drizzle Kit generates forward-only SQL migration files that are committed to the repo and reviewable in PRs.
- Lightweight runtime (~50 KB) with no code generation step blocking dev startup.

## Alternatives Considered

- **Prisma** — excellent DX but the query engine binary adds ~40 MB to the Docker image, and the Prisma schema language is a separate DSL to learn. Schema introspection is harder to machine-edit (important for the AI config agent which needs to read and mutate schema definitions).
- **MikroORM** — solid but less community momentum for new projects in 2025.
- **Raw SQL (pg / postgres.js)** — tempting for performance, but type safety on queries is critical for ledger code.

## Consequences

- All schema changes go through Drizzle migrations in `packages/core/src/db/migrations/`.
- The AI config agent generates Drizzle schema fragments and migration SQL, not raw DDL.
- `drizzle-kit push` is allowed in dev; in production only `migrate` (applying committed migration files) is allowed.
